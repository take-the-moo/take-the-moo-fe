# 서대문 발자취 (가칭)

> 낯선 동네에서 만난 이야기가, 나만의 발자취가 되도록.

외국인 유학생이 서대문의 장소와 이야기를 발견하고, 자신만의 방문 기록을 남기는 모바일 중심 서비스입니다.

어디로 가야 할지 고민하는 순간부터 장소의 의미를 이해하고 하루를 추억하는 순간까지 연결합니다. 모국어와 쉬운 한국어로 이야기를 만나고, 방문 도장과 한 줄 후기 **‘한걸음’**, 회고 엽서로 나의 서대문을 기록하는 경험을 지향합니다.

이 저장소는 **웹과 Capacitor 기반 iOS 앱의 공용 프런트엔드**입니다. 서비스명은 추후 변경될 예정이며, 현재 코드와 앱 설정에서는 `Seoul Storywalk`를 사용합니다.

## 기획 의도

새로운 도시에서의 생활은 가까운 장소를 알아가는 일에서 시작됩니다. 언어와 문화의 차이로 지나치기 쉬운 동네의 이야기를 이해하고, 다른 유학생의 발자취를 따라 걸으며, 자신의 경험도 남길 수 있는 서비스를 만들고자 합니다.

- **발견** — 지금 가기 좋은 장소를 찾아 낯선 동네에서 첫걸음을 뗍니다.
- **이해** — 모국어와 쉬운 한국어로 장소의 이야기를 읽고, 다른 나라의 시선도 만나봅니다.
- **기록** — 도장과 한걸음으로 방문을 남기고, 사진과 소감을 한 장의 엽서로 간직합니다.

## 주요 기능

아래는 서비스가 지향하는 핵심 기능과 현재 프런트엔드 구현 범위입니다.

| 기능 | 서비스 경험 | 현재 구현 |
| --- | --- | --- |
| 처음 설정 | 국적과 언어를 선택하고 시작하기 | 익명 사용자 생성 요청, 기기 내 사용자 정보 저장, 위치 1회 요청 |
| 지금 추천 | 시간·날씨·위치에 맞는 장소와 인기 장소 발견 | 추천 카드·인기 장소 화면, 샘플 데이터 표시 |
| 맞춤 장면 | 모국어·쉬운 한국어로 장소 이야기 읽기 | 장면 화면, 다른 나라 시선 선택 UI, 샘플 이야기 표시 |
| 사진으로 묻기 | 눈앞의 장소를 촬영하고 현장 해설 확인 | 카메라·사진 선택, 장소 선택·검색, 샘플 해설 화면 |
| 방문 도장·나의 기록 | 방문한 장소와 코스 진행 상황 돌아보기 | 도장·코스·날짜별 기록 화면, 샘플 기록 표시 |
| 흔적 지도·한걸음 | 장소별 발자취를 살펴보고 짧은 후기 남기기 | 네이버 지도·필터·장소 카드, 60자 후기와 사진 전송, 저장 실패·422 응답 처리 |
| 회고 엽서 | 사진 4장과 소감·그림체로 하루를 한 장에 담기 | 사진 선택·추가 촬영, 소감·그림체 입력, 생성 진행·결과 화면 시뮬레이션 |

## 사용자 흐름

```text
시작 선택 → 국적·언어 설정 → 지금 추천 → 맞춤 장면
                                         ↓
                                 사진으로 묻기 · 현장 해설
                                         ↓
                                    방문 도장 · 한걸음
                                         ↓
                                 흔적 지도 · 나의 기록
                                         ↓
                                      회고 엽서
```

시작 화면에서 선택적으로 가입·취향 선택 화면을 거칠 수 있습니다.

## 현재 개발 상태

주요 화면과 탐색 흐름을 구현한 **프로토타입**입니다. AI 생성과 실제 데이터 저장은 백엔드 연동이 필요합니다.

- **API 요청 구현**: 사용자 생성과 한걸음 저장에 공통 API 클라이언트를 사용하며, 두 요청 모두 개발용 목(mock) 응답을 제공합니다.
- **샘플 데이터**: 추천·장면·해설·방문 기록·지도 집계는 샘플입니다. 목 모드를 꺼도 이 화면들이 실서버 데이터로 자동 전환되지는 않습니다.
- **가입·취향**: 가입은 UI만 구현되어 있으며 인증 API는 연결되지 않았습니다. 취향은 기기에 저장합니다.
- **다국어**: 화면 문구는 LLM으로 미리 생성한 고정 사전(`src/i18n/messages.ts`)으로 베트남어·중국어·몽골어·영어·일본어를 표시합니다. 언어를 고르기 전에는 기기 언어를 따르고, 지원하지 않는 언어면 영어로 표시합니다. 장소 이야기·해설·후기 번역은 백엔드 연동 전이라 샘플 그대로입니다.
- **회고 엽서**: 실제 AI 생성 API와 결과 이미지가 연결되지 않아 이미지 저장을 완료할 수 없습니다.

| 프레임워크 | Next.js 16.4.5 · App Router, React 19.3.0 |
| 언어 | TypeScript 5 |
| 스타일 | Tailwind CSS 4, 로컬 Noto Sans KR 폰트 |

| 지도 | NAVER Maps JavaScript SDK |

웹과 iOS의 기기 기능 차이는 `src/platform/`에서 처리합니다. 실제 API 요청은 Next.js의 `/api/*` 프록시를 통해 외부 Spring 백엔드로 전달합니다.

## 로컬 실행

### 1. 의존성 설치

`package.json`의 `packageManager`에 지정된 **pnpm 12.16.1**을 사용합니다.

```bash
pnpm install
```

### 2. 환경변수 설정

처음 실행할 때 `.env.example`을 복사합니다. 이미 `.env.local`이 있다면 필요한 값만 수정합니다.

```bash
# 기존 .env.local이 없을 때만 복사
test -f .env.local || cp .env.example .env.local
```

| 변수 | 용도 | 설정 예시 |
| --- | --- | --- |
| `NEXT_PUBLIC_USE_MOCK` | `true`이면 API 클라이언트가 개발용 목 응답 사용 | `true` |
| `API_PROXY_TARGET` | Next.js가 `/api/*` 요청을 전달할 백엔드 주소 | `http://localhost:8080` |
| `NEXT_PUBLIC_NAVER_MAP_KEY_ID` | 네이버 Maps Application Client ID | 발급받은 Client ID |

목 모드에서는 백엔드 없이 화면 흐름을 확인할 수 있습니다. 지도는 별도 설정이 필요합니다. 네이버 Maps Application의 **Web 서비스 URL**에 `http://localhost:3000`을 등록하고 Client ID를 입력하세요. 지도 인증에 실패하면 흔적 지도는 개략도로 표시됩니다.

`NEXT_PUBLIC_*` 값은 브라우저 번들에 노출됩니다. 비밀키를 넣지 않으며, 값을 변경하면 개발 서버를 재시작하거나 배포를 다시 빌드해야 합니다. `.env.example`의 `SKT_ACCESS_KEY_ID`는 현재 코드에서 사용하지 않습니다.

### 3. 개발 서버 실행

```bash
pnpm dev
```

[http://localhost:3000](http://localhost:3000)에서 확인합니다. 첫 실행 시 시작 화면으로 이동합니다.

### 주요 명령어

| 명령어 | 설명 |
| --- | --- |
| `pnpm dev` | 웹 개발 서버 실행 |
| `pnpm build` | Next.js 프로덕션 빌드 |
| `pnpm start` | 빌드된 Next.js 서버 실행 |
| `pnpm lint` | ESLint 검사 |
| `pnpm exec tsc --noEmit --incremental false` | 타입 검사 |
| `pnpm ios` | 개발 모드로 iOS 동기화 후 Xcode 열기 |
| `pnpm cap:sync` | 개발 모드로 iOS 프로젝트 동기화 |

### iOS 개발

macOS와 Xcode 환경에서 웹 개발 서버를 실행한 뒤 `pnpm ios`를 사용합니다. 현재 iOS 앱은 `http://localhost:3000`을 WebView에 로드하는 개발 모드입니다. 실제 기기에서는 개발 PC의 접근 가능한 주소로 별도 설정해야 합니다. Android 프로젝트는 포함하지 않습니다.

## 프로젝트 구조

```text
storywalk-fe/
├── src/
│   ├── app/          # 화면·라우팅·레이아웃·Provider
│   ├── api/          # 공통 API 클라이언트와 오류 처리
│   ├── components/   # 공통 UI·지도·코스 컴포넌트
│   ├── hooks/        # 사진으로 묻기 등 공용 흐름
│   ├── store/        # 사용자·촬영 사진·엽서 상태
│   ├── platform/     # 지도·위치·카메라·알림·공유
│   ├── i18n/         # UI 번역 사전
│   ├── mocks/        # 샘플 데이터·개발용 API 응답
│   └── lib/          # 공용 유틸리티
├── ios/              # Capacitor iOS 프로젝트
├── docs/             # 아키텍처·개발 지침·API 협의 문서
├── capacitor.config.ts
└── next.config.ts    # Next.js 설정·백엔드 API 프록시
```

## 배포

현재 구조는 Next.js 서버 배포를 기준으로 합니다. Vercel에서 이 저장소를 연결할 경우 Root Directory를 `storywalk-fe`로 지정하고 환경변수를 등록합니다. 실제 API 사용 시 `API_PROXY_TARGET`에는 배포 환경에서 접근 가능한 백엔드 주소가 필요하며, 지도에는 배포 도메인을 등록해야 합니다.

`pnpm build`는 Next.js 서버용 빌드입니다. 현재 정적 export 설정이 없어 Capacitor 출시용 `out/` 번들을 생성하지 않습니다. iOS 출시에는 정적 번들·동적 경로·API 연결 방식에 대한 추가 구성이 필요합니다.
